# Описание программного интерфейса (API)

**Обозначение:** UEBA-RS.API.01

**Статус:** дополнительное задание (бонус).

**Сценарий:** «Расчёт и получение Risk Score» — доступ внешних систем (SIEM, дашборд) к результатам модуля через тонкую HTTP-обёртку над ядром скоринга.

## 1. Общие сведения

Таблица – Общие параметры API

| Параметр | Значение |
|---|---|
| Базовый адрес | https://ueba-rs.corp.local/api/v1 |
| Формат данных | JSON, кодировка UTF-8 |
| Аутентификация | Заголовок Authorization: Bearer <токен> |
| Версия | v1 |

## 2. Конечные точки

### 2.1 POST /risk-scores/calculate

Назначение: рассчитать Risk Score для переданных оценок аномальности и центральности. Доступна ролям L2/L3 и администратору.

Таблица – Параметры тела запроса

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| anomaly_scores | object | Да | Словарь «идентификатор объекта → оценка аномальности» |
| centrality_scores | object | Да | Словарь «идентификатор объекта → оценка центральности», ключи совпадают с anomaly_scores |
| weight_anomaly | number | Нет (0.6) | Вес аномальности, от 0 до 1 |
| weight_centrality | number | Нет (0.4) | Вес центральности, от 0 до 1 |
| normalize | boolean | Нет (true) | Выполнять ли нормализацию Min-Max |

Пример запроса:

```json
{
  "anomaly_scores":   {"ivanov_ii": 0.12, "petrov_pp": 0.55, "srv-db-01": 0.90},
  "centrality_scores": {"ivanov_ii": 0.30, "petrov_pp": 0.35, "srv-db-01": 0.85},
  "weight_anomaly": 0.6,
  "weight_centrality": 0.4,
  "normalize": true
}
```

Пример ответа (код 200):

```json
{
  "results": [
    {"object_id": "ivanov_ii", "risk_score": 10.67, "risk_level": "Низкий"},
    {"object_id": "petrov_pp", "risk_score": 46.41, "risk_level": "Средний"},
    {"object_id": "srv-db-01", "risk_score": 100.0, "risk_level": "Критический"}
  ]
}
```

### 2.2 GET /risk-scores/{object_id}

Назначение: получить последний рассчитанный Risk Score объекта. Доступна всем ролям.

Таблица – Параметры

| Параметр | Расположение | Описание |
|---|---|---|
| object_id | Путь | Идентификатор объекта мониторинга |
| history | Запрос, необязательный | Число последних результатов для возврата (по умолчанию 1, максимум 24) |

Пример запроса: GET /risk-scores/srv-db-01?history=1

Пример ответа (код 200):

```json
{
  "object_id": "srv-db-01",
  "object_type": "host",
  "risk_score": 100.0,
  "risk_level": "Критический",
  "calculated_at": "2026-10-28T10:15:03"
}
```

### 2.3 GET /risk-scores/top

Назначение: получить рейтинг объектов с наибольшим Risk Score по последнему расчёту.

Таблица – Параметры запроса

| Параметр | Тип | Описание |
|---|---|---|
| limit | integer | Число объектов, по умолчанию 10, максимум 100 |
| level | string | Фильтр по уровню риска: Низкий, Средний, Высокий, Критический |

Пример запроса: GET /risk-scores/top?limit=2&level=Критический

Пример ответа (код 200):

```json
{
  "calculated_at": "2026-10-28T10:15:03",
  "items": [
    {"object_id": "srv-db-01", "risk_score": 100.0, "risk_level": "Критический"}
  ]
}
```

## 3. Коды ответов

Таблица – Коды ответов

| Код | Значение | Пример причины |
|---|---|---|
| 200 | Успешно | Расчёт выполнен |
| 400 | Некорректный запрос | Длины массивов не совпадают, сумма весов не равна 1,0 |
| 401 | Не пройдена аутентификация | Отсутствует или недействителен токен |
| 403 | Недостаточно прав | Роль L1 вызывает расчёт |
| 404 | Объект не найден | Неизвестный object_id |
| 500 | Внутренняя ошибка | Сбой базы данных |
