# Руководство администратора

**Обозначение:** UEBA-RS.РА.01

**Программа:** Модуль расчёта Risk Score для подсистемы обнаружения аномалий в поведении пользователей (UEBA-RS-1.0)

**Основание:** оформлено по аналогии с ГОСТ 19.503-79 «ЕСПД. Руководство системного программиста»; структура — раздел 3.2 учебного пособия.

## 1. Общие сведения о программе

### 1.1 Назначение и область применения

Руководство предназначено для системного администратора информационной безопасности, отвечающего за установку, настройку, обслуживание и восстановление модуля UEBA-RS-1.0. Модуль рассчитывает Risk Score объектов мониторинга и применяется в SOC-центрах и при мониторинге корпоративных сетей.

### 1.2 Связанные документы

- Руководство оператора (UEBA-RS.РО.01) — работа аналитиков с дашбордом;
- Описание архитектуры и базы данных — устройство системы и схема хранения данных;
- Техническое задание UEBA-RS.ТЗ.01 — требования к программе.

## 3. Установка программы

### 3.1 Требования

Сервер или виртуальная машина (допустим контейнер Docker): процессор x86-64 с 2 ядрами от 2,0 ГГц (рекомендуется 4 ядра от 2,5 ГГц), 4 ГБ ОЗУ (рекомендуется 8 ГБ), 1 ГБ свободного места на диске, ОС Ubuntu 22.04 LTS.

### 3.2 Подготовка системы

Выполните команды от имени администратора:

```bash
sudo add-apt-repository ppa:deadsnakes/ppa
sudo apt update
sudo apt install -y python3.11 python3.11-venv sqlite3 git nginx
sudo useradd --system --create-home --shell /usr/sbin/nologin uebars
sudo mkdir -p /opt/ueba-rs /var/backups/ueba-rs
sudo chown uebars:uebars /opt/ueba-rs /var/backups/ueba-rs
```

### 3.3 Развёртывание программы

```bash
sudo -u uebars git clone <адрес_репозитория> /opt/ueba-rs
cd /opt/ueba-rs
sudo -u uebars python3.11 -m venv .venv
sudo -u uebars .venv/bin/pip install -r requirements.txt
sudo -u uebars cp .env.example .env
sudo chmod 600 .env
```

Файл requirements.txt фиксирует версии зависимостей: pandas не ниже 2.0, numpy не ниже 1.24, streamlit не ниже 1.28, pytest не ниже 7.0.

### 3.4 Инициализация базы данных

```bash
sudo -u uebars .venv/bin/python -m storage init-db
```

Команда создаёт файл базы данных по пути UEBA_DB_PATH, таблицы и индексы, а также запись конфигурации скоринга по умолчанию (веса 0,6 и 0,4, пороги 25, 50, 75).

### 3.5 Запуск служб

Дашборд запускается как служба systemd. Создайте файл /etc/systemd/system/ueba-rs-dashboard.service:

```ini
[Unit]
Description=UEBA-RS dashboard
After=network.target

[Service]
User=uebars
WorkingDirectory=/opt/ueba-rs
ExecStart=/opt/ueba-rs/.venv/bin/streamlit run dashboard/app.py --server.port 8501 --server.address 127.0.0.1
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ueba-rs-dashboard
```

Пакетный расчёт запускается по расписанию cron (раз в час), ежедневный отчёт — в 07:00. Добавьте в crontab пользователя uebars:

```text
0 * * * *  /opt/ueba-rs/.venv/bin/python /opt/ueba-rs/batch_runner.py --once
0 7 * * *  /opt/ueba-rs/.venv/bin/python /opt/ueba-rs/batch_runner.py --report top10
30 2 * * * /opt/ueba-rs/scripts/backup.sh
```

## 4. Настройка программы

### 4.1 Параметры конфигурации

Параметры задаются в файле .env (путь настраивается, права доступа 600).

Таблица – Параметры файла .env

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| UEBA_DB_PATH | ./data/ueba_rs.db | Путь к файлу базы данных SQLite |
| UEBA_RAW_DIR | ./data/raw/ | Каталог сырых журналов |
| UEBA_PROCESSED_DIR | ./data/processed/ | Каталог матриц признаков |
| UEBA_RESULTS_DIR | ./data/results/ | Каталог результатов и отчётов |
| UEBA_LOG_DIR | ./logs/ | Каталог журналов работы |
| UEBA_LOG_LEVEL | INFO | Уровень журналирования: DEBUG, INFO, WARNING, ERROR |
| UEBA_WEIGHT_ANOMALY | 0.6 | Вес аномальности |
| UEBA_WEIGHT_CENTRALITY | 0.4 | Вес центральности |
| UEBA_THRESHOLDS | 25,50,75 | Границы уровней риска |
| UEBA_ALERT_THRESHOLD | 75 | Risk Score, начиная с которого отправляется уведомление в SIEM |
| UEBA_SIEM_URL | (пусто) | Адрес приёма уведомлений SIEM-системы |
| UEBA_SIEM_TOKEN | (пусто) | Токен доступа к SIEM (хранить только в .env) |

### 4.2 Изменение весов и порогов

Сумма весов UEBA_WEIGHT_ANOMALY и UEBA_WEIGHT_CENTRALITY должна быть равна 1,0 с погрешностью не более 1e-6, каждый вес — в диапазоне от 0 до 1. После изменения значений перезапустите службу дашборда командой sudo systemctl restart ueba-rs-dashboard; следующий пакетный расчёт подхватит новые значения. Каждое изменение конфигурации фиксируется новой записью в таблице scoring_config (старая запись помечается неактивной), что позволяет определить, с какими весами получен любой результат.

### 4.3 Настройка журналирования

Журнал работы ведётся в файле logs/ueba_rs.log. Каждая запись содержит поля: временная метка, уровень события, идентификатор объекта, Risk Score, категория риска, сообщение. Пример записи:

```text
2026-10-28 10:15:03 | INFO | srv-db-01 | 100.00 | Критический | Расчёт выполнен
```

Ротация журналов выполняется средствами logrotate (еженедельно, хранить 8 архивов).

## 5. Управление правами доступа и безопасностью

### 5.1 Роли и группы доступа

Аутентификация выполняется на уровне обратного прокси (nginx) через корпоративный каталог пользователей. Роли соответствуют группам каталога.

Таблица – Роли и права доступа

| Роль | Группа каталога | Права |
|---|---|---|
| Оператор L1 | UEBA-RS-Viewers | Просмотр, выгрузка |
| Оператор L2/L3 | UEBA-RS-Analysts | Просмотр, выгрузка, расчёт по требованию |
| Администратор | UEBA-RS-Admins | Все права, доступ к серверу, конфигурации и журналам |

Права выдаются по заявке и пересматриваются не реже одного раза в квартал.

### 5.2 Защита данных и сервера

- Файл .env доступен только пользователю uebars (chmod 600); токен SIEM в репозиторий не добавляется.
- Файл базы данных имеет права 640, каталог резервных копий — 700.
- Дашборд слушает только 127.0.0.1; внешний доступ организуется через nginx с шифрованием TLS.
- Служба работает от непривилегированного пользователя uebars без интерактивной оболочки.
- Тестовые и демонстрационные данные с реальными учётными записями обезличиваются в соответствии с 152-ФЗ.
- Выгрузки (CSV, JSON) содержат идентификаторы учётных записей и хранятся в каталоге results с ограниченным доступом.

## 6. Проверка программы

После установки и после каждого обновления выполните проверку:

```bash
cd /opt/ueba-rs
sudo -u uebars .venv/bin/python -c "import risk_scorer; print('OK')"
sudo -u uebars .venv/bin/pytest tests/ -q
sudo -u uebars .venv/bin/python batch_runner.py --once --dry-run
```

Таблица – Критерии успешной проверки

| Проверка | Ожидаемый результат |
|---|---|
| Импорт модуля | Выведено сообщение OK |
| Модульные тесты | Все тесты пройдены, ошибок нет |

## 7. Мониторинг производительности

Таблица – Контролируемые показатели

| Показатель | Допустимое значение | Как проверить |
|---|---|---|
| Состояние службы дашборда | active (running) | systemctl status ueba-rs-dashboard |
| Возраст последнего расчёта | Не более 2 часов | Страница «Сводка» или запрос к таблице risk_result |
| Число ошибок в журнале за час | Не более 100 | grep -c "\| ERROR \|" logs/ueba_rs.log |
| Время расчёта 10 000 объектов | Не более 5 секунд | Строка «Время расчёта» в журнале пакетного запуска |
| Свободное место на диске | Не менее 20 % | df -h /opt/ueba-rs |
| Размер файла базы данных | Не более 2 ГБ | ls -lh data/ueba_rs.db |
| Доступность системы | Не менее 99,5 % | Время работы службы к общему времени |

При превышении порога числа ошибок (100 в час) администратору отправляется уведомление. Рекомендуется подключить указанные проверки к системе мониторинга предприятия.

## 8. Резервное копирование и восстановление

### 8.1 Что и как копируется

Таблица – План резервного копирования

| Объект | Периодичность | Способ | Срок хранения |
|---|---|---|---|
| База данных | Ежедневно (02:30) | Команда sqlite3 .backup и сжатие | 30 дней |
| Файл .env | При каждом изменении | Копия в защищённое хранилище | Последние 5 версий |
| Исходный код | При каждом изменении | Система контроля версий Git | Постоянно |
| Отчёты в data/results | Еженедельно | Копирование каталога | 90 дней |

Скрипт scripts/backup.sh:

```bash
#!/bin/bash
set -e
DATE=$(date +%F)
sqlite3 /opt/ueba-rs/data/ueba_rs.db ".backup '/var/backups/ueba-rs/ueba_rs_$DATE.db'"
gzip -f /var/backups/ueba-rs/ueba_rs_$DATE.db
find /var/backups/ueba-rs -name "ueba_rs_*.db.gz" -mtime +30 -delete
```

### 8.2 Восстановление из резервной копии

1. Остановите службу и расписание: sudo systemctl stop ueba-rs-dashboard; временно закомментируйте задания cron.
2. Сохраните повреждённый файл базы данных: mv data/ueba_rs.db data/ueba_rs.db.bad.
3. Распакуйте нужную копию: gunzip -c /var/backups/ueba-rs/ueba_rs_ГГГГ-ММ-ДД.db.gz > data/ueba_rs.db.
4. Проверьте целостность: sqlite3 data/ueba_rs.db "PRAGMA integrity_check;" — ожидается ответ ok.
5. Проверьте владельца и права: chown uebars:uebars data/ueba_rs.db; chmod 640 data/ueba_rs.db.
6. Запустите службу, верните задания cron и выполните внеочередной расчёт: batch_runner.py --once.
7. Зафиксируйте инцидент и время восстановления в журнале администратора.

## 9. Дополнительные возможности

### 9.1 Обновление программы

1. Создайте резервную копию базы данных и файла .env.
2. Получите новую версию: git fetch --tags && git checkout <номер_версии>.
3. Обновите зависимости: .venv/bin/pip install -r requirements.txt.
4. Примените изменения схемы базы данных: .venv/bin/python -m storage migrate.
5. Выполните проверку по разделу «Проверка программы» и перезапустите службу.

### 9.2 Передача результатов в SIEM

Если указаны UEBA_SIEM_URL и UEBA_SIEM_TOKEN, экспортёр отправляет уведомление по каждому объекту с Risk Score не ниже UEBA_ALERT_THRESHOLD. Результаты, которые не удалось передать, сохраняются в базе данных с пустым полем exported_at и отправляются при следующем расчёте.

## 10. Сообщения системному администратору

Таблица – Сообщения и действия администратора

| Сообщение | Причина | Действия администратора |
|---|---|---|
| TypeError: anomaly_scores должен быть pd.Series или np.ndarray | Внешний модуль передал данные неподходящего типа | Проверить формат выгрузки модуля Isolation Forest и привести к pd.Series |
| ValueError: Длины массивов не совпадают: anomaly_scores=X, centrality_scores=Y | Разное число объектов в данных аномальности и центральности | Проверить синхронность работы модулей Isolation Forest и NetworkX, повторить расчёт |
| ValueError: Сумма весов должна быть равна 1.0, текущая сумма: X | Некорректные веса в .env | Исправить UEBA_WEIGHT_ANOMALY и UEBA_WEIGHT_CENTRALITY, перезапустить службу |
| ValueError: Веса должны быть в диапазоне [0, 1] | Вес вне допустимых границ | Установить значения от 0 до 1 |
| ValueError: anomaly_scores содержит менее 2 уникальных значений | Недостаточно различных значений для нормализации | Проверить входные данные или временно отключить нормализацию |
| WARNING: Индексы массивов не совпадают | Идентификаторы объектов в двух массивах различаются | Проверить выгрузку из CMDB и модулей-источников |
| sqlite3.OperationalError: database is locked | База данных занята другим процессом | Проверить процессы командой fuser data/ueba_rs.db, дождаться завершения |
| sqlite3.DatabaseError: database disk image is malformed | Повреждён файл базы данных | Восстановить из резервной копии по подразделу «Восстановление из резервной копии» |
| PermissionError при записи в logs/ или data/ | Неверный владелец или права | Выполнить chown -R uebars:uebars logs data |
| ERROR: SIEM недоступен | Нет связи с SIEM или неверный токен | Проверить сеть и токен; неотправленные результаты будут переданы повторно |
| No space left on device | Закончилось место на диске | Очистить старые журналы и отчёты, проверить ротацию |
